# 카카오 실제 지도·장소·자동차 경로 설정

## 무엇이 바뀌었나요?

`장소 찾기`에 카카오 웹 지도, 실제 장소 검색, 출발지·목적지, 최단 거리/최단 시간/추천 경로, 경로 주변 장소 마커, 선택 장소 경유 경로와 추가 시간 비교를 추가했습니다. `가족`에는 사람·반려견·반려묘·기타 반려동물 구분과 반려동물 동반 조건을 추가했습니다. 가상 쉼터 목록은 앱에서 제거했습니다.

앱이 실행됐을 때 보이는 차량 홈의 기본 내비게이션은 Pleos가 제공하는 별도 앱입니다. 여기에 카카오 키를 입력해 동행의 지도가 나타나는 구조가 아닙니다. 새 지도는 **동행 → 장소 찾기**에서 보입니다. 기본 내비게이션이 하얀 이유는 화면만으로 확인할 수 없습니다. 에뮬레이터의 인터넷·위치·그래픽·내비게이션 서비스 상태는 별도로 확인해야 합니다.

## 필요한 API

| 기능 | 서비스 | 키 |
|---|---|---|
| 지도·마커·경로 선 표시 | 카카오 Maps JavaScript API | JavaScript 키 |
| 실제 장소 이름·주소·좌표 검색 | 카카오 로컬 REST API | REST API 키 |
| 자동차 도로 경로·거리·예상 시간 | 카카오모빌리티 길찾기 API | 이용 설정된 REST API 키 |
| 음성→문장 | Android 음성 인식 서비스 | 현재 별도 앱 API 키 없음, 기기 서비스 필요 |
| 문장 의도 분류·위험 규칙 | 앱 내부 모델 | 별도 AI API 키 없음 |

LLM API는 필수가 아닙니다. 현재 간단한 기기 내 분류 모델을 사용합니다. 자연스러운 복합 요청을 더 잘 이해하는 LLM을 추가할 때만 별도 서비스가 필요합니다. 경로와 실제 장소는 AI가 만들어내지 않고 검색·길찾기 API에서 가져옵니다.

카카오 Android 지도 SDK v2의 공식 지원 ABI는 `armeabi-v7a`, `arm64-v8a`입니다. Windows의 x86_64 Pleos 에뮬레이터를 고려해 이번 구현은 **WebView + 카카오 웹 지도**를 사용합니다. 출시 전 차량 앱 심사와 카카오 서비스 이용 조건을 확인해야 합니다.

## 1. 카카오 앱과 키 생성

1. [Kakao Developers](https://developers.kakao.com)에 로그인하고 앱을 생성합니다.
2. 앱 설정의 **플랫폼 키**에서 JavaScript 키를 확인합니다.
3. 해당 JavaScript 키의 **JavaScript SDK 도메인**에 아래 주소를 등록합니다.

   ```text
   http://localhost:8787
   ```

4. 카카오맵 사용 설정/활성화 항목이 표시되면 활성화합니다. 콘솔 메뉴 명칭은 계정과 개편에 따라 다를 수 있습니다.
5. REST API 키도 확인합니다. JavaScript 키와 REST API 키는 서로 바꾸어 쓰지 않습니다.
6. [카카오모빌리티 길찾기 시작하기](https://developers.kakaomobility.com/guide/navi-api/start)에 따라 해당 앱의 서비스 정보와 길찾기 사용 설정을 완료합니다. 계정의 사용 가능 상태·쿼터·요금은 콘솔에서 확인합니다.

이번 웹 지도 방식에는 Android 네이티브 앱 키나 키 해시를 지도 표시용으로 사용하지 않습니다. JavaScript 키는 웹 페이지에서 공개되는 종류의 키이며 등록 도메인 제한을 적용합니다. REST API 키는 서버에만 둡니다. 키를 채팅이나 GitHub에 올리지 마세요.

## 2. PC에서 지도 서버 실행

Python 3.10 이상이 필요합니다. 별도 Python 패키지는 필요 없습니다. 프로젝트 폴더에서 PowerShell을 열고 다음 명령을 입력합니다. 따옴표 안의 두 값은 본인 키로 교체합니다.

```powershell
$env:KAKAO_JAVASCRIPT_KEY = '본인의_JavaScript_키'
$env:KAKAO_REST_API_KEY = '본인의_REST_API_키'
python .\server\server.py
```

길찾기에 다른 카카오 앱의 키를 쓰는 경우에만 서버 실행 전에 다음을 추가합니다.

```powershell
$env:KAKAO_MOBILITY_REST_API_KEY = '길찾기_사용이_설정된_REST_API_키'
```

`python` 명령이 없다면 Python을 설치하고 터미널을 다시 열거나 `py`를 사용하세요. 환경변수 설정은 해당 PowerShell 세션에만 적용됩니다. `.env.example`은 이름을 보여주는 예시 파일이며 서버가 `.env` 파일을 자동으로 읽지는 않습니다.

서버 창을 열어 둔 채 PC 브라우저에서 다음 주소를 엽니다.

```text
http://localhost:8787/map
```

이 단계에서 지도가 떠야 합니다. 안 뜨면 먼저 JavaScript 키·등록 도메인·카카오맵 사용 설정·인터넷을 확인합니다. 서버의 `/health` 주소는 키 자체를 출력하지 않고 설정 여부만 표시합니다.

## 3. 에뮬레이터와 PC 서버 연결

Pleos 에뮬레이터를 켜고 **새 PowerShell 창**에서 실행합니다. 서버를 실행한 기존 창은 그대로 둡니다.

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8787 tcp:8787
```

SDK가 다른 곳에 있다면 SDK Manager에 표시된 실제 SDK 경로를 사용하세요. 기기가 여러 개라면 `adb devices`에 표시된 대상 번호를 지정합니다.

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" -s emulator-5554 reverse tcp:8787 tcp:8787
```

`emulator-5554`는 예시입니다. 실제 번호로 바꾸세요. `adb reverse` 덕분에 앱도 `http://localhost:8787`로 PC 서버에 접근합니다. 앱 주소를 `10.0.2.2`로 바꾸지 않아도 됩니다. 에뮬레이터를 다시 켰다면 연결 명령도 다시 실행하세요.

## 4. 앱 갱신·설정

프로젝트를 갱신한 뒤 `demoDebug` 또는 `pleosDebug`를 빌드·실행합니다.

```powershell
git pull --ff-only
.\gradlew.bat :app:assemblePleosDebug
```

로컬 소스에 직접 수정한 내용이 있어 pull이 거절되면 강제로 덮어쓰지 말고 변경을 먼저 보존하세요. `local.properties`는 Git 관리 대상이 아니므로 SDK 설정은 유지됩니다.

앱에서 **MY → 지도 서비스**로 이동합니다.

- 서버 주소: `http://localhost:8787`
- 서버 연결 토큰: 로컬 기본 실행에서는 빈칸
- 위치·검색어의 지도 서비스 처리 동의: 켜기
- **지도 연결 설정 저장**

로컬 HTTP는 debug 빌드의 `localhost`와 `127.0.0.1`에만 허용했습니다. 공개 배포는 HTTPS 서버가 필요합니다.

## 5. 실제 경로·장소 시험

1. **가족**에서 사람과 반려견/반려묘 등을 등록합니다. 필요하면 `반려동물 동반` 조건을 선택합니다.
2. **장소 찾기**에서 출발지 이름/주소를 검색하고 결과를 선택합니다. GPS를 사용하려면 위치 권한을 허용하고 에뮬레이터에 실제 시험 좌표를 입력합니다.
3. 목적지를 검색하고 결과를 선택합니다.
4. `최단 거리` 또는 `최단 시간`을 고르고 **경로 조회**를 누릅니다.
5. 카카오에서 받은 실제 도로 경로가 파란 선으로 표시됩니다.
6. `휴게소`, `공중화장실`, `애견동반 카페`, `반려견 공원`, `동물병원` 또는 직접 검색어를 입력해 **이 경로 주변 검색**을 누릅니다.
7. 경로 주변의 실제 검색 결과가 지도 마커와 목록으로 표시됩니다. 마커를 누르면 장소명을 확인할 수 있습니다.
8. **경유 경로·추가 시간 보기**를 누르면 해당 장소를 거치는 도로 경로를 다시 계산해 거리·시간 차이를 표시합니다. 체류시간은 포함하지 않습니다.
9. 차량 연동을 시험하려면 먼저 **차량에 목적지 요청**, 이후 **차량 경유지 요청**을 실행하고 Pleos 내비게이션에서 실제 반영을 확인합니다.

음성으로 `경로 근처 애견동반 카페 찾아줘` 같은 요청을 할 수도 있습니다. MY에서 음성 처리에 동의하고 기기에 음성 인식 서비스가 있어야 합니다. 인식 서비스가 없는 에뮬레이터는 입력란과 장소 버튼으로 동일한 검색을 시험하세요.

## 주의할 기능 범위

- 장소가 검색된다는 사실과 기저귀 교환대·수유실·반려동물 출입 허용이 확인됐다는 것은 다릅니다. API가 이 정보를 제공하지 않으므로 ‘미확인’으로 표시합니다. 업체 연락처로 확인하세요.
- 반려동물 동반 조건은 자동 인증 조건이 아닙니다. 실제 검색 후보와 사용자가 직접 확인해 저장한 시설 목록을 구분합니다.
- 경로 검색은 최대 8개 지점, 지점별 15개 결과의 부분 검색입니다. 경로 전체의 모든 장소를 찾는다고 보장하지 않습니다.
- 경로에서 가까워도 반대편 도로거나 진입이 어려울 수 있습니다. 경유 경로 재계산과 차량 내비게이션에서 확인하세요.
- 카카오 경로와 Pleos 경로는 데이터·교통·탐색 기준이 달라 다를 수 있습니다. 이 기능은 경로 계획·미리보기이며 실시간 턴바이턴 내비게이션 엔진은 아닙니다.
- 실제 API 키가 없는 환경에서는 지도·검색·실제 경로 호출을 완료할 수 없습니다. 빈 결과를 가상 장소로 채우지 않습니다.
- 이 Python 서버는 로컬 개발용입니다. 외부 서비스는 HTTPS·연결 토큰·사용자 인증·서버 측 호출 제한·요금 관리가 필요합니다.
